# SalaryClock 설계 문서

작성일: 2026-09-22

## 1. 개요

SalaryClock은 지금 이 순간 내 급여가 얼마나 쌓였는지 실시간으로 보여주는 웹앱이다.
연봉과 근무시간을 한 번 입력해두면, 출근 시각부터 초 단위로 적립되는 금액과
매끄럽게 움직이는 아날로그 시계를 한 화면에서 보여준다.

서버도 데이터베이스도 로그인도 없다. 전부 브라우저 안에서 끝난다.

## 2. 범위

### v1에 포함

- 오늘 하루의 적립 금액 (초 단위 갱신)
- 스위프 방식 아날로그 시계 (현재 시각)
- 근무시간 진행률 (시계 바깥 링)
- 퇴근까지 남은 시간과 남은 금액
- 설정: 급여, 근무시간, 점심시간
- 설정값 로컬 저장

### v1에서 제외 (YAGNI)

- 주/월/연 누적 통계
- 주말·공휴일·연차 처리
- 실수령액(4대보험·소득세) 환산
- 커피·치킨 환산, 회의비용 타이머
- 계정, 서버, 여러 기기 동기화

제외 항목은 모두 나중에 붙일 수 있다. v1의 계산 모듈이 순수 함수라
누적 통계는 날짜 범위를 돌며 같은 함수를 호출하는 것으로 확장된다.

## 3. 사용자 화면

단일 페이지, 스크롤 없음.

```
┌──────────────────────────────────────┐
│                                  ⚙   │
│            ╭─────────╮               │
│          ╱   12        ╲             │  아날로그 시계
│         │  9  ╲│    3   │            │  바깥 링 = 근무시간 진행률
│          ╲      6      ╱             │  점심 구간은 링에서 비워둠
│            ╰─────────╯               │
│                                      │
│           ₩ 47,382                   │  적립 금액
│             +38 / 초                 │
│                                      │
│   퇴근까지 04:12:33 · 남은 ₩41,618   │
└──────────────────────────────────────┘
```

시계 하나가 "지금 몇 시인지"와 "하루 중 어디쯤인지"를 동시에 말해준다.
별도 프로그레스 바를 두지 않는다.

## 4. 계산 모델

### 4.1 입력 (설정값)

| 항목 | 타입 | 기본값 | 비고 |
|---|---|---|---|
| `payMode` | `'annual' \| 'monthly' \| 'hourly'` | `'annual'` | 급여 입력 방식 |
| `payAmount` | number | 50,000,000 | 원 단위 |
| `workDaysPerMonth` | number | 21.75 | `annual`·`monthly`일 때만 사용 |
| `workStart` | `"HH:mm"` | `"09:00"` | 출근 |
| `workEnd` | `"HH:mm"` | `"18:00"` | 퇴근 |
| `lunchEnabled` | boolean | true | |
| `lunchStart` | `"HH:mm"` | `"12:00"` | |
| `lunchEnd` | `"HH:mm"` | `"13:00"` | |

### 4.2 파생값

```
근무구간초   = (workEnd - workStart)              // 자정 넘으면 +24h
점심초       = lunchEnabled ? (lunchEnd - lunchStart) : 0
유급초/일    = 근무구간초 - 점심초

초당임금 =
  annual   → payAmount / (12 × workDaysPerMonth × 유급초/일)
  monthly  → payAmount / (workDaysPerMonth × 유급초/일)
  hourly   → payAmount / 3600
```

`hourly`는 근무일수 가정이 필요 없으므로 `workDaysPerMonth`를 무시한다.

### 4.3 출력

계산 함수는 설정값과 현재 시각을 받아 다음을 돌려준다.

```ts
{
  phase: 'before' | 'working' | 'lunch' | 'after',
  earned: number,          // 오늘 지금까지 적립액 (원)
  perSecond: number,       // 초당 적립액, 점심·근무외에는 0
  progress: number,        // 0..1, 유급시간 기준
  elapsedPaidMs: number,
  totalPaidMs: number,
  msUntilStart: number,    // 출근까지 남은 시간, 이미 출근했으면 0
  msUntilEnd: number,      // 퇴근까지 실제 시계 시간 (점심 포함), 퇴근 후면 0
  remainingAmount: number, // 오늘 남은 적립액
}
```

`before` 상태에서는 `msUntilStart`를, 나머지 상태에서는 `msUntilEnd`를 화면에 쓴다.

### 4.4 상태별 동작

| phase | earned | perSecond | 화면 문구 |
|---|---|---|---|
| `before` | 0 | 0 | 출근까지 HH:mm:ss |
| `working` | 경과유급초 × 초당임금 | 초당임금 | 퇴근까지 HH:mm:ss |
| `lunch` | 점심 시작 시점 값으로 고정 | 0 | 점심시간 · 재개까지 mm:ss |
| `after` | 하루치 전액 | 0 | 오늘 근무 종료 |

## 5. 아날로그 시계

### 5.1 스위프 운동

초침이 1초마다 끊기지 않고 연속으로 흐른다. 분침과 시침도 마찬가지로
눈금 사이를 계속 이동한다.

```ts
const t = now.getTime() - startOfDay   // ms
초침각 = (t % 60_000)      / 60_000      * 360
분침각 = (t % 3_600_000)   / 3_600_000   * 360
시침각 = (t % 43_200_000)  / 43_200_000  * 360
```

밀리초를 버리지 않고 그대로 각도로 환산하는 것이 핵심이다.

### 5.2 구현 제약

- **CSS transition을 바늘에 걸지 않는다.** 각도가 360도에서 0도로 넘어가는
  순간 역방향으로 한 바퀴 도는 현상이 생긴다. 매 프레임 각도를 직접 지정한다.
- SVG `transform` 속성만 갱신한다. DOM 구조는 재생성하지 않는다.
- 틱 소스는 `requestAnimationFrame` 하나뿐이다. 시계 바늘과 금액 카운터가
  같은 틱을 쓰므로 둘이 어긋나지 않는다.

### 5.3 근무 진행 링

문자판 바깥에 호(arc)를 그린다. 시침 위치 기준으로 정렬하므로
09:00은 9시 방향, 18:00은 6시 방향에서 끝난다.

- 배경 호: 출근~퇴근 전 구간
- 진행 호: 출근~현재. 끝점은 `progress` 비율이 아니라 **현재 시각의 각도**다
- 점심 구간: 배경·진행 모두 비워 "여기는 돈이 안 붙는다"를 보여준다

진행 호를 현재 시각에 맞추고 점심 구간을 비워두면, 실제로 칠해진 호의 길이가
유급 진행률과 자연히 일치한다. 두 값을 따로 계산해 어긋나게 두지 않는다.

근무시간이 12시간을 넘으면 호가 한 바퀴를 넘어 겹친다. 이 경우 링을
한 바퀴로 clamp하고, 진행률 수치를 텍스트로 함께 표시한다.

### 설계 원칙

**저장되는 상태는 설정값뿐이다.** 적립액은 어디에도 저장하지 않고
매 프레임 `계산(설정, 현재시각)`으로 새로 구한다. 탭을 닫았다 열어도,
절전에서 깨어나도, 시계가 어긋날 구조적 여지가 없다.

**계산은 시각을 인자로 받는다.** `lib/salary.ts`는 `Date.now()`를 직접
호출하지 않는다. 테스트에서 임의 시각을 주입할 수 있고, 나중에 누적 통계를
붙일 때 과거 날짜로 같은 함수를 호출하면 된다.

## 7. 설정 저장

- `localStorage` 키: `salaryclock.settings.v1`
- 읽을 때 zod로 검증한다. 깨졌거나 스키마가 안 맞으면 기본값으로 되돌린다.
- 저장된 설정이 없으면 첫 화면에서 설정 패널을 먼저 연다.
- 서버 렌더와 클라이언트 값이 달라 생기는 hydration 불일치를 피하기 위해,
  설정은 마운트 이후에 읽고 그 전에는 기본값으로 렌더한다.

## 8. 엣지 케이스

| 상황 | 처리 |
|---|---|
| 퇴근 시각 ≤ 출근 시각 | 자정을 넘는 야간근무로 보고 퇴근에 24h를 더한다 |
| 야간근무 중 자정 통과 | 현재 시각을 오늘 시프트·어제 시프트 두 후보로 평가해 해당하는 쪽을 쓴다 |
| 점심이 근무구간 밖 | 설정 저장 시 검증해서 거부한다 |
| 점심이 근무시간 전체 | 유급초가 0이 되므로 거부한다 |
| 출근 == 퇴근 | 거부한다 |
| 근무시간 12시간 초과 | 링은 한 바퀴로 clamp, 진행률은 텍스트 병기 |
| 탭 백그라운드 | rAF가 멈춘다. 복귀 시 현재 시각으로 다시 계산하므로 보정이 필요 없다 |
| 시스템 시계 변경 | 매 프레임 현재 시각을 새로 읽으므로 자동으로 따라간다 |
| `prefers-reduced-motion` | 초침 스위프를 1초 단위 갱신으로 낮춘다 |

## 9. 기술 스택

- Next.js (App Router) + TypeScript
- Tailwind CSS
- zod (설정 검증)
- vitest (계산 로직 테스트)

서버 코드 없음. 전부 클라이언트 렌더. Vercel에 그대로 배포된다.

## 10. 테스트 전략

`lib/salary.ts`가 순수 함수이므로 계산 로직은 DOM 없이 전부 테스트한다.
구현 전에 테스트를 먼저 쓴다 (TDD).

테스트할 것:

- 급여 방식 3종의 초당임금 산출
- 출근 전 / 근무 중 / 점심 중 / 퇴근 후 각 phase 판정
- 점심 경계 직전·직후 금액 연속성 (점심 시작 시점에 고정, 종료 시점에 재개)
- 하루 종료 시 적립액 == 일급 (부동소수점 오차 허용범위 내)
- 자정을 넘는 야간근무 시프트
- 진행률 0 / 0.5 / 1 지점
- 설정 스키마 검증: 잘못된 시각, 뒤집힌 구간, 근무구간 밖 점심

시계 각도 계산도 순수 함수로 분리해 경계값(59.999초, 자정)을 테스트한다.

## 11. 확장 여지

v1 구조에서 자연스럽게 이어지는 것들:

- 누적 통계 — 날짜 범위를 돌며 같은 계산 함수 호출
- 실수령액 — 초당임금에 공제율을 곱하는 레이어 추가
- 재미 환산 — 표시 레이어에서 금액을 나누기만 하면 됨
- 설정 URL 공유 — 설정을 쿼리스트링으로 직렬화
